# Blog Improvement Plan

Date: 2026-09-14
Project: `portfoli-x`
Scope: Improve existing `content/blog/*.md` posts, strengthen internal backlinks, make the article index/table of contents visible, and make Algorithm Visualizer embeds feel useful inside blogs.

## 1. Current State

The site already has the right building blocks:

- Blog content lives in `content/blog/`.
- Algorithm reference content lives in `content/algorithms/`.
- Blog pages render through `app/blog/[pageId]/page.tsx`.
- Markdown rendering supports GFM tables, math, callouts, wikilinks, lazy images, heading slugs, and algorithm embeds.
- Algorithm embeds are supported with fenced code blocks such as:

~~~md
```algo:binary-search
```
~~~

- Backlinks are already computed from `[[wikilinks]]` and `/blog/{slug}` links in `features/blog/lib/graph.ts`.
- `components/blog/TableOfContents.tsx` exists, but blog detail pages currently do not render the collected ToC.

Main gaps:

- Blog structure is inconsistent: some posts use `#` inside the article while others start at `##` or `###`.
- Several posts are too thin or have placeholder-like metadata dates.
- Backlinks are possible, but posts do not intentionally link to related posts or algorithm references.
- Algorithm Visualizer is technically available, but blog posts are not using it.
- There is no visible article index/table of contents despite the renderer collecting heading data.

## 2. Target Blog Format

Every problem-solving blog should use this concise, repeatable structure:

~~~md
---
title: "Problem Name"
description: "One specific sentence about the core idea and technique."
published: YYYY-MM-DD
thumbnail: _assets/thumbnails/example.webp
tags:
  - Leetcode
  - Monotonic Stack
  - Arrays
category: Blog
---

## Index

Generated by the page UI from headings. Do not hand-maintain unless the UI is unavailable.

## Problem

Short restatement in your own words, plus source links.

## Pattern

Name the reusable pattern and link related notes with wikilinks.

Example: This is a [[monotonic-stack]] contribution-counting problem.

## Intuition

Explain the core idea in 5-8 lines.

## Visual Walkthrough

```algo:stack
```

## Approach

Step-by-step algorithm.

## Dry Run

Use a compact table for one representative input.

## Code

One primary language first. Add other languages only when they add value.

## Complexity

| Metric | Value | Why |
|---|---:|---|
| Time | `O(n)` | Each element is pushed and popped once. |
| Space | `O(n)` | Stack and helper arrays. |

## Common Mistakes

List edge cases, duplicate handling, overflow, indexing traps, and constraints.

## Related

- [[sum-of-subarray-minimums]]
- [[subarrays-with-first-element-minimum]]
- [Algorithm Visualizer: Stack](/algorithms/stack)
~~~

Rules:

- Use `##` for top-level article sections because the page already renders the post title as `h1`.
- Keep explanations direct. Make the article more detailed by adding examples, dry runs, edge cases, and "why it works", not by adding filler.
- Prefer one excellent implementation before adding multiple languages.
- Use tables for examples, dry runs, complexity, and edge cases.
- End with a `Related` section to intentionally create outgoing links and backlinks.

## 3. Index Table / Table Of Contents Work

Goal: every blog has an automatic, clickable index based on headings.

Implementation steps:

1. Update `app/blog/[pageId]/page.tsx` to call `renderMarkdownWithToc` instead of `MarkdownRenderer`.
2. Render `components/blog/TableOfContents.tsx` in the sticky sidebar above `DynamicGraphView`.
3. On mobile, render a compact ToC above the article body or inside a collapsible section.
4. Keep the article title as the only `h1`; normalize post headings to start at `##`.
5. Hide ToC when a post has fewer than three headings.
6. Rename the visual label from "Table of Contents" to "Index" if you want it to match your wording.

Target files:

- `app/blog/[pageId]/page.tsx`
- `components/blog/TableOfContents.tsx`
- `components/global/MarkdownRenderer.tsx`
- `styles/markdown.css`

Acceptance criteria:

- Blog detail pages show a sticky index on desktop.
- Mobile users can access the same index without layout overlap.
- Clicking an index item scrolls to the correct section and updates the URL hash.
- No post manually duplicates the generated index unless needed for a special article.

## 4. Backlink Strategy

Goal: make the blog feel like a connected knowledge base, not isolated posts.

Use `[[slug]]` links inside content wherever the relationship is meaningful. The backlink system currently recognizes blog-to-blog links. For algorithm reference pages, use normal links until graph support is expanded:

```md
Related patterns: [[sum-of-subarray-minimums]], [[subarrays-with-first-element-minimum]]

See also: [Binary Search Visualizer](/algorithms/binary-search)
```

Priority internal links:

| Blog | Add Links To | Why |
|---|---|---|
| `sum-of-subarray-minimums.md` | `[[subarrays-with-first-element-minimum]]`, `/algorithms/stack`, `/algorithms/sliding-window` if relevant | Connect monotonic stack family posts. |
| `subarrays-with-first-element-minimum.md` | `[[sum-of-subarray-minimums]]`, `/algorithms/stack` | Reinforce contribution/counting pattern. |
| `valid-sudoku.md` | `/algorithms/sudoku-solver`, `/algorithms/hash-table`, `/algorithms/backtracking` if added | Connect validation to solver and set/bitmask patterns. |
| `game-of-xor.md` | `/algorithms/big-o-notation`, related XOR contest posts | Add prerequisites and reusable bitwise context. |
| `greatest-sum-divisible-by-three.md` | `/algorithms/greedy-vs-dp`, `/algorithms/memoization` | Clarify DP/greedy framing. |
| `maximum-total-value-k-subarrays.md` | `/algorithms/dynamic-programming` pages where available | Connect to interval/DP thinking. |
| Contest posts | Problem-specific standalone posts and algorithm visualizer pages | Let readers jump from contest summary to deep explanations. |

Code improvement to consider:

- Extend `features/blog/lib/graph.ts` so it can also recognize `/algorithms/{slug}` links and add algorithm nodes to the graph.
- Rename "Mentioned In" to "Backlinks" or "Referenced By" for clarity.
- Add an "Outgoing Links" or "Related Notes" component under each post.

Acceptance criteria:

- Every blog has at least 3 useful internal links.
- Every article ends with a `Related` section.
- Backlinks section is non-empty for major cluster posts.
- Graph view shows meaningful content clusters rather than only shared-tag connections.

## 5. Algorithm Visualizer Improvements

Goal: use Algorithm Visualizer inside blogs as the main learning aid, not a decorative widget.

Content usage:

- Add one visualizer embed near the first explanation of the reusable pattern.
- Use only matching algorithms. For example:
  - `valid-sudoku.md`: `sudoku-solver` or `hash-table`
  - `sum-of-subarray-minimums.md`: `stack`
  - `subarrays-with-first-element-minimum.md`: `stack`
  - `greatest-sum-divisible-by-three.md`: `greedy-vs-dp` or `memoization`
  - `game-of-xor.md`: add a future `xor` visualizer or link to Big O until available
  - Graph posts: `bfs`, `dfs`, `dijkstra`, `topological-sort`
  - Search posts: `binary-search`, `linear-search`, `jump-search`, `interpolation-search`

Component improvements:

1. Make embedded mode more compact:
   - reduce border radius from `rounded-2xl` to `rounded-lg`;
   - keep canvas height stable at mobile and desktop sizes;
   - make header text wrap safely on small screens;
   - keep the standalone link visible but unobtrusive.
2. Add an optional caption from Markdown:

~~~md
```algo:binary-search
Binary search narrows the search interval by half after every comparison.
```
~~~

3. Support optional props later:

~~~md
```algo:binary-search {"speed":1.5,"autoplay":false}
```
~~~

4. Improve failure states:
   - show a clear message when an algorithm slug is invalid;
   - link to `/algorithms` so readers can recover.
5. Add a post-level checklist to ensure embedded visualizers do not appear before the reader knows what they are seeing.

Target files:

- `lib/content/markdown/algorithms.ts`
- `components/blog/AlgorithmEmbedHydrator.tsx`
- `features/algorithms/components/AlgorithmVisualizer.tsx`
- `features/algorithms/components/AlgorithmCanvas.tsx`
- `features/algorithms/components/StepController.tsx`

Acceptance criteria:

- Embedded visualizers render in blog posts with no layout shift.
- Controls are usable on mobile.
- Invalid algorithm slugs fail gracefully.
- Each visualizer is introduced by text and followed by the lesson it demonstrates.

## 6. Content Rewrite Priorities

### Priority 1: High-impact single-problem posts

Start here because these can become polished evergreen articles.

| File | Improvements |
|---|---|
| `content/blog/sum-of-subarray-minimums.md` | Normalize headings, add index support, add stack visualizer, tighten duplicate-handling explanation, add edge-case table, backlink to related subarray post. |
| `content/blog/subarrays-with-first-element-minimum.md` | Normalize headings, add stack visualizer, compare with sum-of-subarray-minimums, add proof of next-smaller logic. |
| `content/blog/valid-sudoku.md` | Expand from short note to full article: examples, invalid cases, row/column/box indexing diagram, bitmask alternative, link to Sudoku solver visualizer. |
| `content/blog/greatest-sum-divisible-by-three.md` | Add DP state table, dry run, why keeping min removals works, and DP/greedy related links. |

### Priority 2: Contest posts

Contest posts need a consistent summary-first structure.

Use this format:

- `## Contest Summary`
- `## Index`
- `## Problem A: Title`
- `## Problem B: Title`
- `## Problem C: Title`
- `## Takeaways`
- `## Related`

Improvements:

- Add a compact table with problem, pattern, difficulty, link, and final complexity.
- Add backlinks from contest problems to deeper standalone articles.
- Split any problem that deserves evergreen search traffic into its own post.
- Keep contest posts concise; move deep explanations to standalone posts.

### Priority 3: Thin or incomplete posts

`content/blog/leetcode-weekly-contest-494.md` is currently very short. Either expand it into the full contest format or mark it as a stub/draft if the content system supports drafts later.

## 7. Metadata Cleanup

Current `published` values such as `2001-08-30`, `2001-09-25`, and `2001-11-23` look like placeholders. Fix them before relying on recency sorting.

Steps:

1. Decide whether `published` means original solve date or public article date.
2. Use real ISO dates.
3. Add `updated` when a post receives a major rewrite.
4. Make descriptions more specific and search-friendly.
5. Standardize tags:
   - `Leetcode`
   - `GeeksforGeeks`
   - `AtCoder`
   - `Dynamic Programming`
   - `Monotonic Stack`
   - `Bit Manipulation`
   - `Prefix Sum`
   - `Graph`
   - `Backtracking`

Acceptance criteria:

- Blog listing order is intentional.
- Tags cluster related posts predictably.
- Descriptions explain the technique, not just the platform.

## 8. Implementation Sequence

### Phase 1: Make Index Visible

- Wire `renderMarkdownWithToc` into the blog detail page.
- Render `TableOfContents` in the sidebar.
- Verify on desktop and mobile.

### Phase 2: Normalize Blog Template

- Convert all article body headings to start at `##`.
- Add consistent sections: Problem, Pattern, Intuition, Approach, Code, Complexity, Common Mistakes, Related.
- Keep contest posts in a separate contest summary template.

### Phase 3: Add Backlinks

- Add meaningful `[[blog-slug]]` links in the body and Related sections.
- Add algorithm links with `/algorithms/{slug}`.
- Optionally extend graph/backlinks to include algorithm nodes.

### Phase 4: Add Algorithm Visualizer Embeds

- Add ` ```algo:{slug}` embeds to posts where a matching visualizer exists.
- Improve embedded visualizer spacing, mobile behavior, captions, and errors.
- Add or define missing visualizers only when a post has a real teaching need.

### Phase 5: Deepen Content Without Bloat

- Add dry-run tables.
- Add edge cases.
- Add proof/why-it-works sections.
- Remove duplicate code blocks unless multiple languages are truly needed.
- Prefer concise transitions and concrete examples.

### Phase 6: Verify

- Run `pnpm lint`.
- Run `pnpm typecheck`.
- Run `pnpm build`.
- Smoke test:
  - `/blog`
  - `/blog/sum-of-subarray-minimums`
  - `/blog/valid-sudoku`
  - `/algorithms/stack`
  - one blog with an embedded visualizer.

## 9. Definition Of Done

- Every blog has a visible generated index/table of contents when enough headings exist.
- Every blog has a consistent heading hierarchy.
- Every major blog has at least one visual example, dry run, or Algorithm Visualizer embed.
- Every blog has a Related section with useful backlinks.
- Backlinks and graph views show real relationships, not only shared tags.
- Metadata dates, tags, and descriptions are accurate.
- Build, lint, and typecheck pass after the changes.
